How This System Works

A plain-language map of every moving part: what runs when, what each file is responsible for, what the concepts actually mean, and what's worth improving next. No assumed background — if a term needs jargon, it gets explained the moment it's used.

00 The One-Paragraph Version

Every day, this system downloads the latest NIFTY 50 prices, hands them to four different "guessers" (a plain no-change guess, a straight-line fit, a tree-based model, and a neural network) who each predict tomorrow's full candle — Open, High, Low, Close — and separately, tomorrow's percent move. Rather than trusting any one guesser by default, it tests all four fairly on years of real held-out history and only lets the one that's actually earned it make today's call. That prediction becomes an options trade idea. Every prediction gets written down, and — this is the important part — checked against what actually happens once the next real day arrives, building an honest, permanent track record instead of a one-time guess.

03 The Daily Pipeline, Step by Step

This is what actually happens inside train.py's run_pipeline() — the function behind both the dashboard's "Run Forecast" button and a plain python train.py.

flowchart TD A["Fetch the latest data"] --> B["Build feature windows
(20 past days -> predict day 21)"] B --> C["Hold out the most recent
7 years (1,764 days)"] C --> D["Train each model on
everything BEFORE the holdout"] D --> E["Score all 4 fairly on the
untouched holdout days"] E --> F["Pick the winner
(lowest error — Naive excluded)"] F --> G["Fold the holdout back in
(now that the real outcomes are known)"] G --> H["Predict tomorrow
from the winning model"] H --> I["Build an options strategy
from that prediction"] I --> J["Log every model's guess,
not just the winner's"] J --> K["Reconcile any earlier
predictions now resolved"] K --> L["Regenerate report.md"]
Twelve steps, same order, every single run.
Why "hold out, then fold back in" instead of just training on everything If a model is tested on the same data it learned from, that test proves nothing — like grading someone on an exam they already saw the answer key for. Holding out real days it hasn't seen yet, scoring it there, and only afterward letting it learn from them keeps the test honest.

06 Core Concepts, Explained Without Jargon

What "training" a model actually means

A model starts out knowing nothing — its internal numbers are close to random. Training is a loop: show it a real example, let it guess, tell it how wrong the guess was, and nudge its internal numbers slightly in the direction that would have made the guess better. Do that enough times over enough examples, and the nudges add up to something that's actually learned a pattern.

Why raw prices never get fed in directly

NIFTY was around 5,000 a decade ago and around 24,000 now. A model fed raw prices would waste effort learning "what year is this" instead of learning real candle-to-candle behavior. Every price gets expressed as a ratio to a recent reference point instead — "1.02" always means "2% above where we started," in any year.

The four models — four different ways of thinking

ModelHow it actually thinks
NaiveNo thinking at all — "tomorrow will look like today." Exists purely as the honesty check every other model has to beat.
Linear RegressionFits the simplest possible straight-line relationship between the inputs and the answer.
XGBoostBuilds a sequence of decision trees, each one correcting the previous trees' mistakes — good at finding threshold rules like "if RSI is high AND the market has been falling."
LSTMA neural network that reads the 20-day window like a sentence, keeping a running "memory" of what it's seen so far.

Why predict the % move separately from the candle

The % move is normally only ever derived after the fact from a model's predicted Close. The "direct" and "returns-only" tracks instead train a model whose only job is that one number — no Open/High/Low to also get right. This tests whether specializing helps, versus asking one model to do everything at once.

The options strategies, in plain terms

  • Bull Call Spread / Bear Put Spread — a directional bet: "I think it's going up" (or down), sized to limit both the cost and the maximum loss.
  • Iron Condor — a bet that the market stays calm; profits if the price doesn't move much.
  • Long Straddle — a bet that something big is coming, without knowing which direction.

Which one gets suggested depends on comparing the winning model's predicted move against what India VIX implies is "normal" for that many days.

Why Naive is shown everywhere but can never win

Naive always predicts "no change" — which, fed into the strategy engine, unconditionally produces an Iron Condor, regardless of what's actually likely. It stays in every comparison as the honesty floor, but it's excluded from actually being picked to drive the live prediction, for exactly that reason.

A deliberate limitation This report only states facts — predicted X, actual Y, off by Z. It never guesses at why something went wrong. That interpretation is left to whoever reads it (you, or an LLM you hand it to).

08 What Real Data Has Shown So Far

A few genuine, evidence-backed findings from the first real days of live tracking:

  • LSTM showed a consistent bias — every real day, it predicted a noticeably wider candle than what happened, overshooting Close by roughly 2.6–3.7%, every single time. Traced to a real training weakness (full-batch gradient descent meant "150 epochs" was really just 150 total update steps) and fixed with mini-batch training — not yet confirmed on new real data whether this resolved it.
  • Linear Regression has been a strong, cheap performer — the lowest Close error of all four models across the first several tracked days.
  • Every real day so far has been unusually calm — so the strategy engine hasn't yet been tested on a genuinely volatile day, which is the scenario that matters most.

09 How This Can Be Improved

Ranked roughly by how much it would actually move the needle, not by how interesting it sounds:

  1. Connect walk-forward evidence to daily model selection. Right now walk-forward is purely informational — it never changes what tomorrow's forecast does. Closing that loop, carefully, is the next real step (see below).
  2. Let the live Model Scoreboard mature. Every real day genuinely adds new evidence; no shortcut replaces this.
  3. Test the log-return target formulation — an open question raised early on and never actually tried: does predicting log-returns instead of simple ratios change accuracy?
  4. Feature importance for XGBoost (e.g. SHAP) — since it's currently the strongest tree-based performer, understanding which inputs it actually relies on could guide what to add or drop.
  5. A confidence-based "no trade" threshold — right now a strategy always gets suggested; letting the system say "not confident enough to trade today" when models disagree sharply is a natural extension.
  6. More cross-market context (e.g. S&P 500 overnight return) — discussed early on, deliberately deferred to avoid overfitting an already-small dataset.
